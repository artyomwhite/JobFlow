# JobFlow — руководство пользователя

JobFlow — личный кабинет для поиска вакансий. Он собирает объявления из подключённых источников, распределяет их по профилям поиска и помогает вести собственную очередь откликов. Сервис не отправляет отклики за вас: статус «Откликнулся» устанавливается только по вашей команде.

## Первый запуск

1. Подготовьте PostgreSQL базу и заполните `.env.local` по образцу `.env.example`. Для Neon используйте pooled URL в `DATABASE_URL`, а direct URL в `DIRECT_URL`.
2. Создайте длинные случайные значения `BETTER_AUTH_SECRET` (не менее 32 символов) и `OWNER_SETUP_TOKEN` (не менее 24 символов). Не вставляйте их в чат и не сохраняйте в Git.
3. Установите зависимости, примените миграцию, создайте Prisma Client и начальные профили/источники:

   ```powershell
   npm install
   npm run db:migrate
   npm run db:generate
   npm run db:seed
   ```

4. Запустите `npm run dev`, откройте `http://localhost:3000/register` и создайте единственную учётную запись владельца. Токен регистрации берётся из `OWNER_SETUP_TOKEN`.
5. После регистрации удалите `OWNER_SETUP_TOKEN` из окружения и перезапустите/переразверните приложение. Для обычного входа используйте `/login`.

Если аккаунт создан раньше начального заполнения, повторный `npm run db:seed` привяжет стартовые профили без перезаписи уже изменённых профилей.

## Ежедневная работа

### Главная

Показывает количество уникальных вакансий, совпадений по профилям, внешних переходов и подтверждённых откликов. В блоке профилей видно число новых вакансий. В блоке источников отображается состояние интеграций. «Recent activity» — последние действия.

Кнопка **Refresh all profiles** запускает сбор по всем включённым профилям. Это ручная операция: расписание и фоновый сбор не настроены. После завершения страница обновится и покажет число новых вакансий. Ошибки отдельных источников попадают в историю синхронизаций; другие доступные источники при этом продолжают обрабатываться.

### Профили и очередь

Стартово создаются профили Project Manager, Product Manager, Full-Stack Developer, React Developer, Next.js Developer, Node.js Developer, Python Developer и AI / ML Engineer. В **Settings** можно изменить их или добавить профиль под другую роль.

В профиле задайте название, поисковые ключи (по одному на строку), исключаемые ключи, город/локацию и диапазон опыта. Сбор сопоставляет ключевые слова с заголовком и описанием вакансии; исключённые слова и завышенные требования к опыту отфильтровываются. Выключенный профиль не участвует в следующем сборе.

Откройте профиль и нажмите **Refresh profile**, чтобы обновить только его. Список показывает совпадения, процент оценки и текущий статус. Фильтры позволяют просматривать все вакансии, новые, сохранённые, отмеченные как отклик и пропущенные.

### «Next vacancy» — просмотр по одной вакансии

Кнопка **Next job** открывает первую новую вакансию в очереди профиля. Просмотр записывается автоматически один раз за вкладку/сессию браузера.

Действия доступны кнопками и горячими клавишами:

- `S` — сохранить в подборку;
- `A` — подтвердить, что вы отправили отклик;
- `K` — пропустить;
- `L` — отложить.

Горячие клавиши работают только на странице «Next vacancy» и не срабатывают, когда курсор находится в поле ввода. **Open original** открывает исходное объявление и записывает внешний переход. Переход на сайт вакансии сам по себе не считается откликом.

### Saved и Applied

**Saved vacancies** — закладки. Их можно снова открыть или отметить другим действием.

**Applied** содержит вакансии, где вы нажали `A`/**Applied**. Для каждой записи можно хранить заметки, ответ компании и этап: Applied, No response, Recruiter screen, Interview, Offer, Rejected или Withdrawn. Общая запись об отклике считается один раз на вакансию, даже если она подошла нескольким профилям.

### History и Analytics

**History** показывает до 200 последних действий: просмотр, переход, сохранение, отклик, пропуск и отложенное.

**Analytics** агрегирует реальные данные и позволяет выбрать период: сегодня (по Киеву), 7 дней, 30 дней или всё время. Включает уникальные вакансии, совпадения, просмотры, внешние переходы, подтверждённые отклики, конверсию кликов в отклик и разбивку по профилям/источникам. Это учёт действий, а не обещание точной эффективности поиска.

## Источники вакансий

На момент этой версии реально подключены публичные RSS-ленты Djinni и DOU Jobs и публичная JSON-лента Happy Monday. Jooble требует `JOOBLE_API_KEY`, поэтому по умолчанию ждёт настройки. Robota.ua, Work.ua, LinkedIn Jobs, Lobby X и Wellfound отображаются как недоступные/не настроенные, и приложение не имитирует подключение и не обходит авторизацию или ограничения сайтов.

JobFlow удаляет параметры отслеживания из ссылок для дедупликации и связывает найденные копии с канонической вакансией. Для каждой вакансии сохраняется источник-оригинал и дополнительные найденные ссылки. Если источник временно недоступен, синхронизация записывается как неудачная для него, но интеграция не отключается навсегда.

## Безопасность и данные

- Регистрация первого владельца доступна только через одноразовый `OWNER_SETUP_TOKEN`; публичная регистрация закрыта.
- Пароль обрабатывается Better Auth и не сохраняется открытым текстом. Сессии хранятся в базе, а серверные страницы и API проверяют активную сессию и владельца записи.
- Профили, действия, синхронизации и заявки фильтруются по ID пользователя. Не передавайте токен владельца и базовые ключи интеграции сторонним автоматизациям.
- `.env.local` исключён из Git. Не добавляйте URL базы, секреты, пароль или ключ Jooble в коммиты.
- Для удаления данных/миграций используйте процедуры резервного копирования и штатные операции базы; `db:migrate` применяет миграции без сброса таблиц.

## Настройка на Vercel и Neon

Создайте в Vercel переменные `DATABASE_URL`, `DIRECT_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`. `OWNER_SETUP_TOKEN` добавляется только на время первоначальной регистрации; `JOOBLE_API_KEY` — только при подключении Jooble. До первого запуска приложения примените миграцию к Neon (`npm run db:migrate`), затем заполните каталог (`npm run db:seed`). После регистрации владельца удалите установочный токен и выполните redeploy.

В проекте пока нет настроенного cron, почтовых/Telegram-уведомлений, публичных ключей для интеграций и приглашений пользователей. Архитектура оставляет сервисы, API и события расширяемыми, но эти подключения ещё предстоит отдельно настроить и проверить.
